# Modules in the web app

Each module can have a web package that exports `defineModule({ .. })` (`web/src/kernel/modules/define.ts`). The build's packages come from `web/src/modules.generated.ts`, generated by `make modules` from `back/aphel.modules.toml` (imported as `@modules/<key>`). Everything the module registers carries its key and is filtered by the enabled set from `GET /api/v1/modules`: with the module disabled, routes, menu, tabs, slots, filters, overrides, field types, translations and commands disappear without reloading the page. Full architecture: [`docs/architecture/web-modules.md`](../architecture/web-modules.md).

```ts
export default defineModule({
  key: 'lead_pro',
  translations: { 'pt-BR': () => import('./i18n/pt-BR.json'), en: () => import('./i18n/en.json') },
  namespaces: { notifications: { 'pt-BR': { kinds: { lead_pro_hot: { label: 'Lead esquentou', description: '…' } } } } },
  settingsPanel: undefined,
  register(app) {
    app.routes([{ path: 'lead-pro', children: [{ index: true, lazy: async () => ({ Component: (await import('./BoardPage')).BoardPage }) }] }])
    app.nav({ to: '/lead-pro', label: 'nav', icon: Flame, permission: 'lead_pro.read', order: NAV_ORDER.modules })
    app.recordTab('contact', { key: 'lead_pro.temperature', label: 'tab', icon: Flame, permission: 'lead_pro.read', render: TemperatureTab })
    app.slot('record.detail.actions', { key: 'lead_pro.touch', recordTypes: ['contact'], render: TouchButton })
    app.fieldType('number:lead_temperature', { Input: TemperatureInput, Display: TemperatureDisplay })
    app.command({ id: 'lead_pro.board', label: 'board.title', icon: Flame, to: '/lead-pro' })
  },
})
```

## Registration

| Method | Contributes |
| --- | --- |
| `routes(routes, { layout })` / `publicRoutes` | App routes (`layout: 'app'` by default, or `'bare'`) and public routes without a session. Routes behind the `ModuleGate` |
| `nav(item)` | Sidebar item (`order`, `permission`, `badge`) |
| `settings(area, item)` | Settings item (`account`, `organization`, `integrations`, `data`) with its own page |
| `recordTab(types, tab)` | Tab on the record detail page (`render` receives `recordType`, `recordId`, `readOnly`; the optional `useVisible` hides the tab depending on the data) |
| `recordList(extension)` | Extra filter fields and title adornment in record lists (`use` returns `{ filterFields, titleAddon }`) |
| `slot(name, contribution)` | Component at a named point of the screen |
| `filter(name, fn, priority)` | Transformation of a list (columns, layout, tabs, menu, commands, sections) |
| `override(id, component)` | Replaces a component marked with `<Overridable id>` |
| `fieldType(type, { Input, Display })` | Input and display of a field type, or of a specific field with `'<type>:<key>'` |
| `timelineRenderer(type, r)` / `eventRenderer(event, r)` | Timeline item |
| `widget(key, renderer)` | Dashboard widget (the data part comes from the backend's `app.widget`) |
| `command(command)` | Palette command (`Ctrl K`) |
| `createAction(action)` | "Create" item in the palette, the `+` button and the `C` shortcut (`recordType` ties the action to the open list; `targetRecordTypes` + `linkedLabel` create the "create linked" command on the detail page) |
| `quickAdd({ key, label, title?, icon, permission, order, linksRecord?, recordShortcut?, render })` | Option of the mobile "Quick add" (the `+` button in the bottom bar). `render` receives `initialRecord` (the record of the open page, unless `linksRecord` is `false`) and `onDone`; `recordShortcut` becomes the floating button on record pages (e.g. the "Check-in" from `activities`). The forms use the building blocks from `features/mobile` (`RecordPicker`, `DictationField`, `QuickForm`, `useOutboxFeedback`) and submit through the offline queue (`submitWithOutbox`) |
| `referenceOptions(type, provider)` | Options of a reference selector (`pipeline_stage`, `tag`, `sequence`, `segment`, `activity_type`…) used by automations, bulk actions and other modules without importing the owner |
| `timelineSource(factory)` | Default timeline source of a record (registered by the `timeline` module) |
| `configPackageLabels(labels)` | Labels for the module's configuration package sections, types and properties |
| `settingsPanel` | Custom panel on the modules screen (without it, the form is built from the manifest's `SettingField`s) |
| `translations` / `namespaces` | The module's namespace (`= key`) and keys added to other namespaces (e.g. the label of a notification kind in `notifications:kinds.<kind>`). Each language is an object or a loader (`() => import('./i18n/en.json')`) |

### Record types

Wherever a contribution takes record types (`recordTab`, slot `recordTypes`, `recordList`, `targetRecordTypes`), a selector applies: `'contact'`, a list, a pattern ending in `*` (`'co_*'` = all custom objects, `'*'` = all) or a function `(recordType) => boolean`.

### Contributions with hooks

`recordTab(..).useVisible` and `recordList(..).use` are hooks. The kernel calls those of **all** registered contributions, always in the same order (registration only happens at boot), passing `enabled: false` when the module is disabled, the type does not match or a permission is missing; the hook must always call the same hooks and only turn off the queries (`enabled`). Results must be memoized (`useMemo`), because the kernel compares by reference.

```ts
app.recordList({
  key: 'tags',
  recordTypes: isTaggable,
  use: ({ recordType, records, enabled }) => {
    const tags = useTags(recordType, { enabled })
    return useMemo(() => ({ filterFields: .., titleAddon: .. }), [..])
  },
})
```

### Reference selectors

The owner registers `app.referenceOptions('pipeline_stage', { use: (context) => ({ options, isLoading }), queryKey })` (`options` = `{ value, label, group? }`; `context` carries `recordType` and `includeInactive`). Consumers use `<ReferenceOptions kind context>{({ options }) => ..}</ReferenceOptions>`, `useHasReferenceOptions(kind)` to hide the action when no enabled module provides the type, and `useReferenceQueryKeys([..])` to invalidate the owner's cache after a write.

### On-demand translations

With loaders, only the active language (and the default `pt-BR`, used as a fallback) is downloaded; the build bundles each language's JSON files into one chunk (`locales-pt-BR`, `locales-en`). The kernel never lets a raw key show up: the app only mounts after the translations of the required modules, `ModulesSync` loads the translations of the modules about to be enabled before applying the enabled set, and switching languages (`switchLanguage`, used by `applyLanguage`) downloads the new language before calling `i18n.changeLanguage`. Code outside a module that needs a namespace without the module being active (e.g. a public page) loads the JSON on its own.

Texts always go through i18n: `useModuleTranslation(key)` for the module's namespace; labels of `nav`, `recordTab`, `settings` and `command` are keys in the module's namespace (or `namespace:key`). After creating or moving JSON files, run `npm run i18n:types`.

## Slots

`<Slot name props />` renders the enabled contributions, filtered by `recordTypes` and `permission`.

| Slot | Props | Where |
| --- | --- | --- |
| `record.detail.title` | `recordType`, `record`, `readOnly` | Next to the record title |
| `record.detail.header` | same | Below the title (e.g. the call summary on the activity detail page, from `calls`) |
| `record.detail.actions` | same | Record header buttons (e.g. "Merge with…" from `duplicates`) |
| `record.detail.sidebar` | same | Side column of the detail page |
| `record.fields.panel` | same | Fields panel of the detail page |
| `record.list.toolbar` | `recordType`, `filter`, `applyFilter` | List toolbar |
| `record.list.viewActions` | `recordType`, `viewId` | Saved view actions |
| `record.list.rowActions` | `recordType`, `record` | Menu of each row |
| `record.list.bulkActions` | selection context | Bulk actions |
| `record.form.sections` | `recordType`, `mode`, `record` | Extra form sections |
| `dashboard.top` | — | Top of the dashboard |
| `composer.tools` | `context`, `subject`, `value`, `onChange` | Tools of the note, email and message composer |
| `user.menu` | — | User menu |
| `app.shell` | — | Global components of the app shell |
| `app.sidebar` | `collapsed`, `onNavigate` | End of the sidebar |
| `catalog.sections` | `entries` | After the modules section of Settings › Catalog; the module renders the entries of the kinds it handles |

## Filters

`app.filter(name, (value, context) => newValue, priority)`; readers use `useFilters`/`applyFilters`.

| Filter | Value | Context |
| --- | --- | --- |
| `records.columns` | list columns (`FieldDefinition[]`) | `recordType` |
| `records.formLayout` | form layout | `recordType`, `mode` |
| `records.detailTabs` | detail tabs | `recordType`, `record`, `readOnly` |
| `navigation.items` | menu items | — |
| `commands` | palette commands | — |
| `settings.sections` | settings groups | `area` |
| `deals.tone` | tone (color) of a deal on the board | deal |

## Routes and home page

Module routes are behind the `ModuleGate`. The root `/` belongs to `dashboard`; with it disabled (or outside the build) the kernel redirects to the first enabled menu item (`HomeFallback`). An unknown route falls into the top-level 404: with a session, inside the app layout; without a session, a public 404 (it does not lead to the login).

## Overrides

`app.override(id, Component)` replaces the component; the replacement receives the same props.

| Id | Screen |
| --- | --- |
| `contacts.ListPage`, `contacts.DetailPage` | Contact list and detail |
| `companies.ListPage`, `companies.DetailPage` | Company list and detail |
| `leads.Page` | Lead inbox |

To make a screen of your module overridable, wrap it in `<Overridable id="<key>.<Screen>" component={Screen} props={..} />`.

## Field types

`FieldInput` and `FieldValueDisplay` look up the type registry (native types registered by the kernel in `native-field-types.ts`). Lookup order: `'<type>:<field key>'` (that field only, like `lead_pro`'s `number:lead_temperature`), then `'<type>'` (all fields of the type), then the native one. `Input` receives `FieldInputProps` (`field`, `value`, `onChange`, `disabled`, `invalid`, accessibility labels); `Display` receives `field` and `value`.

## Web package outside `web/src/modules`

A plugin can keep its web package in its own crate and declare `[package.metadata.aphel] web = "web"`. `make modules` writes the `@modules/<key>` alias to `web/modules.aliases.json` (Vite, with `server.fs.allow`) and `web/tsconfig.modules.json` (TypeScript). The package imports `@/…` from Aphel and only libraries that `web/` already installs; `npm run i18n:types` also reads `i18n/pt-BR.json` from the packages listed in `web/modules.aliases.json`.
