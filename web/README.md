# Aphel Web

Aphel's frontend: React 19 + TypeScript + Vite 8, Tailwind CSS v4, in-house components on top of Radix (shadcn style), React Router 7, TanStack Query 5, react-hook-form + zod and i18next (pt-BR default).

The build (`web/dist`) is embedded in the backend binary via `rust-embed`. In development, Vite proxies `/api`, `/_aphel` and `/p/` to `http://127.0.0.1:3001`.

## Scripts

| Script | What it does |
| --- | --- |
| `npm run dev` | Vite development server with a proxy to the backend |
| `npm run build` | Typecheck (`tsc -b`) and production build in `dist/` |
| `npm run preview` | Serves the build locally |
| `npm run lint` | oxlint |
| `npm run typecheck` | `tsc -b --noEmit` |
| `npm test` | Vitest in single-run mode (`vitest run`) |
| `npm run test:watch` | Vitest in watch mode |
| `npm run api:types` | Generates `src/api/schema.d.ts` from the backend's OpenAPI |

### API types

`npm run api:types` runs `scripts/generate-api-types.mjs`, which tries, in this order:

1. `http://127.0.0.1:3001/api/openapi.json` (can be overridden with `APHEL_OPENAPI_URL`);
2. the `../back/openapi.json` file, if it exists.

It also accepts an explicit path: `npm run api:types -- path/to/openapi.json`.

`openapi-typescript` 7 depends on the TypeScript 5 JavaScript API, which does not exist in the TypeScript 7 used by the project. That is why it is isolated in `scripts/api-types/` (with its own `typescript@5` and lockfile), installed automatically by the script on the first run.

## Structure

```text
src/
  app/                 application composition
    App.tsx            RouterProvider + providers
    AppProviders.tsx   i18n, TanStack Query, theme, tooltips, toasts
    routes.tsx         routes (layout, home, 404)
    query-client.ts    default QueryClient
    layout/            AppLayout, Sidebar (collapsible), MobileSidebar (drawer below md), Topbar, navigation
    theme/             ThemeProvider, useTheme, ThemeToggle
  api/                 single access point to the API
    client.ts          fetch with base /api, credentials: "include", X-Organization-Id header
    errors.ts          ApiError from the envelope { error: { code, message, details } }
    organization.ts    getter/setter for the active organization
    schema.d.ts        types generated by openapi-typescript (do not edit by hand)
  components/ui/       Button, Input, Label, Select, Dialog, DropdownMenu, Toast, Skeleton,
                       EmptyState, ErrorState, Badge, Card, Tooltip
  features/<feature>/  screens and logic per feature (home, not-found, ...)
  i18n/                i18next; one JSON per namespace in <locale>/<namespace>.json (pt-BR default, en empty)
  lib/                 utilities (cn, safe storage, theme)
  test/                Vitest setup and render helpers
scripts/               Node scripts (API type generation)
```

## Conventions

- Code in English; UI texts only through i18n (`useTranslation('<namespace>')`). The key types come from `src/i18n/i18next.d.ts`.
- HTTP calls only through `src/api` (`api.get/post/put/patch/delete` or `apiRequest`). Errors arrive as `ApiError` (`status`, `code`, `message`, `details`).
- Base UI components live in `src/components/ui`; combine classes with `cn()` from `src/lib/utils.ts`.
- The `@/` alias points to `src/`.

## Theme

- CSS tokens in `:root` (light) and `[data-theme='dark']` in `src/index.css`, exposed to Tailwind via `@theme inline` (`bg-primary`, `text-muted-foreground`, ...).
- `light | dark | system` preference saved in `localStorage` (`aphel.theme`); the resolved theme goes to `document.documentElement.dataset.theme`. System mode follows `prefers-color-scheme` in real time.
- The primary color can be overridden at runtime with `applyPrimaryColor(color)` from `src/lib/theme.ts` (sets `--primary` on the root element), the basis for per-organization visual identity.
